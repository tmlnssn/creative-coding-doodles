# Creative Coding Doodles — Claude Code Instructions

## Project Context

This repository is a personal creative coding playground for a Digital Design / ICT & Media Design student.

The goal is to explore JavaScript as a creative design tool through small experiments involving visual design, generative graphics, motion and interaction.

The focus is on learning by doing, understanding the underlying code and exploring possibilities rather than building polished or finished products.

## Learning Approach

Follow the exploratory approach inspired by the Creative Vibe Doodling workshop:

**Make → Observe → Question → Change → Share**

- **Make:** Start with something extremely small and visible.
- **Observe:** Examine the result and understand how the code works.
- **Question:** Explore why something behaves a certain way and what might happen if one element changes.
- **Change:** Modify one thing at a time and observe the effect.
- **Share:** Document discoveries, variations and questions.

Avoid jumping ahead to a complete concept or finished application.

## Technology

- Start with Vanilla JavaScript, HTML and CSS.
- Avoid frameworks and external libraries unless explicitly requested.
- Use the Canvas 2D API where appropriate for visual experiments.
- Keep the code simple, readable and beginner-friendly.
- Prioritize understanding fundamental JavaScript concepts before introducing unnecessary abstractions or dependencies.
- Introduce new technologies only when they serve a specific experimental or learning goal.

## Coding Guidelines

- Make only the changes explicitly requested.
- Change one thing at a time whenever possible.
- Preserve existing code and structure unless a change is necessary.
- Avoid unnecessary features, animations, interactions or visual embellishments.
- Prefer simple solutions over complex or highly optimized implementations.
- Use descriptive variable names and clear code organization.
- Add comments only when they help explain something important.
- Do not refactor working code without being asked.

## Learning Support

- Briefly explain what new or modified code does.
- Highlight relevant JavaScript concepts in accessible language.
- Explain unfamiliar methods, properties or syntax when asked.
- Help me understand code rather than memorize syntax.
- Use concrete examples from the current doodle.
- Avoid overwhelming explanations or introducing too many concepts at once.
- Encourage small manual changes when they are useful for learning.

## Working Together

I use ChatGPT separately for brainstorming, creative direction, learning reflections and documenting my experiments.

Your primary role is to help me write, modify, understand and troubleshoot code directly in VS Code.

When I request a change:

1. Implement only the requested change.
2. Briefly explain what changed and why.
3. Wait for my next instruction.

Do not automatically implement or propose multiple next steps.

When I ask a question about existing code, explain it without modifying any files unless explicitly requested.

## Repository Structure

Each doodle lives in its own numbered folder, for example:

```text
creative-coding-doodles/
├── 01-circle/
│   └── index.html
├── 02-example/
│   └── index.html
├── README.md
└── CLAUDE.md
```

- Keep experiments independent wherever practical.
- For simple doodles, prefer a single `index.html` containing HTML, CSS and JavaScript.
- Introduce separate files only when complexity makes them useful or when explicitly requested.
- Keep each doodle small enough to explore and understand in a short session.

## Guiding Principle

**Start small. Change one thing. Understand what happens. Stay curious.**

AI supports the coding process, but creative decisions, experimentation and learning remain central.
